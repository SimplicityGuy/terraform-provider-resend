# resend_domain (Resource)

Manages a Resend sending domain. Creating the resource adds the domain to Resend, which generates the DNS records (`records`) that prove you own it. Publish those records with your DNS provider, then use `resend_domain_verification` to ask Resend to check them.

Resend generates the DNS records when the domain is created, so `records` is only known
after the first apply. Changing `name`, `region` or `custom_return_path` deletes the domain
and adds it again, which means publishing and verifying a new set of records.

## Example Usage

```terraform
resource "resend_domain" "example" {
  name   = "updates.example.com"
  region = "eu-west-1"

  open_tracking  = true
  click_tracking = true
  tls            = "enforced"
}

# The records to publish with your DNS provider.
output "dns_records" {
  value = resend_domain.example.records
}
```

### Publishing the records with Cloudflare

This example adds the domain, publishes every record Resend generates in a Cloudflare zone
with `cloudflare_dns_record` (Cloudflare provider v5), and then asks Resend to verify the
domain. The same pattern works with any DNS provider's record resource.

```terraform
# Add a domain to Resend, publish the DNS records Resend generates in a
# Cloudflare zone, then ask Resend to verify them.
#
# The provider block reads RESEND_API_KEY and CLOUDFLARE_API_TOKEN from the
# environment. The Cloudflare token needs Zone Read and DNS Edit permission on
# the zone.

terraform {
  required_providers {
    resend = {
      source  = "SimplicityGuy/resend"
      version = "~> 0.1"
    }
    cloudflare = {
      source  = "cloudflare/cloudflare"
      version = "~> 5.0"
    }
  }
}

provider "resend" {}

provider "cloudflare" {}

variable "cloudflare_zone_id" {
  description = "The Cloudflare zone for the root domain, such as example.com."
  type        = string
}

variable "domain" {
  description = "The domain to send from: the zone itself or a subdomain of it."
  type        = string
  default     = "updates.example.com"
}

data "cloudflare_zone" "this" {
  zone_id = var.cloudflare_zone_id
}

resource "resend_domain" "this" {
  name = var.domain
}

locals {
  zone_name = data.cloudflare_zone.this.name

  # Key each record by its purpose, type and name, which are unique within a
  # domain. Resend returns names relative to the root domain (send.updates for
  # updates.example.com), and some, such as the Tracking record, fully
  # qualified; normalize them all to fully qualified names.
  resend_records = {
    for r in resend_domain.this.records : "${r.record}/${r.type}/${r.name}" => merge(r, {
      fqdn = r.name == local.zone_name || endswith(r.name, ".${local.zone_name}") ? r.name : "${r.name}.${local.zone_name}"
    })
  }
}

# Resend generates the records when the domain is created, so on the first
# apply the set of records isn't known yet and for_each can't be planned.
# Create the domain first, then apply the rest:
#
#   terraform apply -target=resend_domain.this
#   terraform apply
resource "cloudflare_dns_record" "resend" {
  for_each = local.resend_records

  zone_id  = var.cloudflare_zone_id
  name     = each.value.fqdn
  type     = each.value.type
  content  = each.value.value
  priority = each.value.priority == "" ? null : tonumber(each.value.priority)
  ttl      = 1 # automatic, which is what Resend's "Auto" asks for
  proxied  = false
  comment  = "Resend ${each.value.record} record for ${resend_domain.this.name}"
}

# Ask Resend to check the records once they are published.
resource "resend_domain_verification" "this" {
  domain_id = resend_domain.this.id

  depends_on = [cloudflare_dns_record.resend]
}

output "verification_status" {
  value = resend_domain_verification.this.status
}
```

`for_each` needs the record set at plan time, and it doesn't exist until Resend creates the
domain. Create the domain on its own first (`terraform apply -target=resend_domain.this`,
or `tofu apply -target=resend_domain.this`), then run a full apply. Later applies need no
`-target` unless the domain is replaced.

## Schema

### Required

- `name` (String) The domain to send from, such as `updates.example.com`. Resend recommends a subdomain rather than the root domain. Changing it replaces the domain.

### Optional

- `click_tracking` (Boolean) Whether Resend tracks link clicks for this domain. Defaults to `false`.
- `custom_return_path` (String) The subdomain Resend uses for the Return-Path (bounce) address, such as `outbound`. Resend uses `send` when it is not set. It can only be set when the domain is created, so changing it replaces the domain.
- `open_tracking` (Boolean) Whether Resend tracks email opens for this domain. Defaults to `false`.
- `region` (String) The region Resend sends the domain's email from. Valid values: `us-east-1`, `eu-west-1`, `sa-east-1`, `ap-northeast-1`. Defaults to `us-east-1`. Changing it replaces the domain.
- `tls` (String) How Resend uses TLS when delivering mail. `opportunistic` tries a secure connection and falls back to sending unencrypted when the receiving server does not support TLS; `enforced` refuses to deliver without TLS. Valid values: `enforced`, `opportunistic`. Defaults to `opportunistic`.

### Read-Only

- `created_at` (String) When the domain was created, as reported by Resend.
- `id` (String) The Resend domain ID, a UUID. Use it with `terraform import` and wherever another resource needs the domain (`resend_domain_verification`, `resend_api_key`).
- `records` (Attributes List) The DNS records to publish so Resend can verify the domain. Resend generates the set when the domain is created, so it is only known after the first apply. (see [below for nested schema](#nestedatt--records))
- `status` (String) The verification status of the domain: one of `not_started`, `pending`, `verified`, `partially_verified`, `partially_failed`, `failed` or `temporary_failure`.

### Nested Schema for `records`

Read-Only:

- `name` (String) The record name relative to the root domain, such as `send` or `resend._domainkey` (`send.updates` for the subdomain `updates.example.com`). Some records, such as `Tracking`, are returned fully qualified.
- `priority` (String) The MX priority, as a string (for example `10`). Empty for record types that have no priority.
- `record` (String) What the record is for, as Resend labels it: `SPF`, `DKIM`, and, depending on the domain's settings, records such as `Tracking` or `Receiving`.
- `status` (String) The verification status of this record: one of `not_started`, `pending`, `verified`, `failed` or `temporary_failure`.
- `ttl` (String) The time to live Resend recommends. `Auto` means the DNS provider's default.
- `type` (String) The DNS record type, such as `MX`, `TXT` or `CNAME`.
- `value` (String) The record content. Publish it exactly as returned: the SPF TXT value includes its surrounding quotes.

## Import

Import a domain by its Resend domain ID.

In Terraform v1.5.0 and later, and OpenTofu v1.5.0 and later, use an
[`import` block](https://developer.hashicorp.com/terraform/language/import):

```terraform
import {
  to = resend_domain.example
  id = "d91cd9bd-1176-453e-8fc1-35364d380206"
}
```

Or use the `terraform import` (or `tofu import`) command:

```shell
# Import a domain by its Resend domain ID.
terraform import resend_domain.example d91cd9bd-1176-453e-8fc1-35364d380206
```

The provider can't read `open_tracking`, `click_tracking`, `tls` or `custom_return_path`
back from Resend, so they aren't filled in on import. The next apply sets `open_tracking`,
`click_tracking` and `tls` to the values in your configuration (or their defaults), so set
them to match the domain's current settings first.
