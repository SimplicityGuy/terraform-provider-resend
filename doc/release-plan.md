# Release plan

This plan maps the work that gets SimplicityGuy/resend from a fresh hard fork of
[y0n0zawa/terraform-provider-resend](https://github.com/y0n0zawa/terraform-provider-resend) to a
stable v1.0.0. Each release ships a fixed, named set of work items. The release number follows from
what that work changes for users.

The work is tracked as beads in the `tfresend` beadhive hive. Bead IDs (`tfresend-…`) are listed
so each line of the plan can be traced to the bead that delivers it. **The beads are the source of
truth.** This document is a snapshot of the plan as of 2026-10-28; update it when the plan changes.

> `docs/` is reserved for the Terraform/OpenTofu registry documentation generated by
> tfplugindocs, so project documents like this one live in `doc/`.

## Versioning

- **SemVer, independent of the SDK.** The version describes the provider's own HCL and state
  compatibility. It does not follow resend-go's major version. Every release's notes, and the
  provider's User-Agent, record the resend-go version it was built with.
- **0.x while the API coverage is filled in.** Commitizen runs with `major_version_zero = true`,
  so a `feat` commit bumps the minor and a `fix` commit bumps the patch. A release whose work is
  only fixes is a patch release; one that adds schema is a minor release.
- **v1.0.0 is the stability commitment.** From v1.0.0 on, breaking HCL or state changes need a new
  major version, deprecations land in a minor version, and removals land only in a major.
- **Tags** are annotated `vX.Y.Z` tags (Commitizen `tag_format = "v$version"`, `version_scheme =
  "semver2"`).
- **No version predates the fork.** GitHub copied upstream's tags into this repository when it was
  forked. On 2026-10-28 they were renamed to `upstream/v0.1.0`, `upstream/v1.0.0` and
  `upstream/v1.0.1` (same commits), so they stay referenceable, Commitizen ignores them, and this
  provider's own `v0.1.0` is free.
- **The first release is exactly v0.1.0.** The Commitizen version file starts at `0.0.0`
  (unreleased); with `major_version_zero`, the first bump yields `0.1.0`. Its CHANGELOG entry
  describes the fork baseline (upstream v1.0.1) rather than replaying upstream's history.

### Prereleases

Release candidates use SemVer 2.0 prerelease identifiers: **`v1.0.0-rc.1`, `v1.0.0-rc.2`, …**

- The dot in `rc.1` matters: SemVer compares dot-separated numeric identifiers numerically, so
  `rc.10` sorts after `rc.9`. `rc10` would be compared as text and sort before `rc2`.
- Numbering starts at `rc.1` (Commitizen `prerelease_offset = 1`). Commitizen would otherwise
  start at `rc.0`.
- Terraform and OpenTofu select a prerelease **only** when the configuration pins it exactly
  (`version = "1.0.0-rc.1"`). `~>` and `>=` constraints never pick one up, so an RC can't reach
  users who didn't ask for it.
- GoReleaser publishes `-rc.N` tags as GitHub prereleases (`release.prerelease: auto`). The
  Terraform Registry may show the newest RC as "latest" until v1.0.0 ships. That only affects
  the registry listing; `terraform init` still won't select it.

### Gating

Releases are cut from `main`, so anything merged before a tag ships in that release. To keep every
release's contents exactly as listed, **each release's work starts only after the previous
release is tagged.** For example, the webhook bead can't start until v0.2.0 is out. The cost is
less parallelism after v0.1.0: one release's work (two or three beads) is in flight at a time.

The gate covers work that changes the provider. The two spikes and other documentation-only work
(`docs:` / `chore:` commits) aren't gated: they don't bump the version, and Commitizen leaves them
out of the CHANGELOG.

## Prerequisites and risks

- **GitHub-side setup (`infra-zcp`, infra hive).** The repository left the fork network on
  2026-10-28. The rest of this bead adopts it into the SimplicityGuy github module with the
  repository standards and seals the Actions secrets: a Resend API key for a dedicated test
  account, the release GPG key and its passphrase. Acceptance CI (`vtt`) and v0.1.0 depend on it.
  Beads can't depend across hives, so this ordering is by convention: land `infra-zcp` first.
- **GitHub Actions billing (`infra-ddy`, infra hive).** On 2026-10-27, GitHub refused Actions runs
  account-wide ("recent account payments have failed or your spending limit needs to be
  increased"). Until that's resolved, CI, the acceptance tests and `release.yml` can't run, and no
  release can ship.
- **A dedicated Resend test account.** The acceptance tests create real domains, keys and webhooks.
  They must never run against a production account.
- **The release signing key.** RSA 4096, not ECC: the Terraform Registry rejects ECC keys. It's
  used only for releases and registered with both registries. The private key reaches CI only as
  the sealed Actions secret.

## Cutting a release

Each release bead's acceptance criteria apply to every release:

1. `just bump-preview` on `main` proposes exactly the planned version (`0.1.0` for the first
   release). If it doesn't, the merged commits don't match the plan; stop and fix the plan or the
   commits.
2. `just bump` writes the CHANGELOG entry and the annotated tag. Check the CHANGELOG lists only
   this release's beads.
3. Pushing the tag runs `release.yml`, which publishes the signed assets. The release notes record
   the resend-go version.
4. Confirm both registry.terraform.io and registry.opentofu.org list the version, and that
   `terraform init` and `tofu init` (with `OPENTOFU_ENFORCE_GPG_VALIDATION=true`) install it signed
   by the published key.

For the release candidates and v1.0.0:

- **v1.0.0-rc.1:** set `major_version_zero = false`, then
  `cz bump --prerelease rc --increment MAJOR`.
- **v1.0.0-rc.N:** `cz bump --prerelease rc` after merging the fix.
- **v1.0.0:** `cz bump` from the last RC, on the RC's commit. The CHANGELOG folds the RC entries
  into v1.0.0.

## Upgrading from y0n0zawa/resend

SimplicityGuy/resend is a separate provider address. Existing upstream users need a one-time state
migration rather than a version bump. The full guide ships with v1.0.0-rc.1
(`docs/guides/migrating-from-y0n0zawa.md`). In short:

```sh
terraform state replace-provider registry.terraform.io/y0n0zawa/resend registry.terraform.io/SimplicityGuy/resend
tofu state replace-provider registry.opentofu.org/y0n0zawa/resend registry.opentofu.org/SimplicityGuy/resend
```
